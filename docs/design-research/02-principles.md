# 調査から抽出した設計原則

## 1. ポートフォリオを作るのではなく、ブログをよく編集する

このサイトで最も説得力がある情報は、スキル名や記事数ではなく、2019年からの具体的な題名と本文である。したがってトップの役割は自己宣伝ではなく、内容の入口を編集することとする。

### トップに残す

- サイト名
- 1〜3文の短い紹介
- 降順の記事タイムライン
- 年、タグ、検索
- 2〜3本の編集上のおすすめ
- About、GitHub、Qiita、RSS

### トップから外す候補

- 記事数、年数、外部投稿数の常設パネル
- `01 / 02 / 03` の同寸トピックカード
- 大型の「記事を読む」CTA
- `Selected Work` に相当する実績セクション
- 意味が重複する英大文字ラベル

### ポートフォリオ性を担う場所

`About` へ次の小さな節を置く。

- **現在**: 今扱っている技術や関心
- **これまで**: 経歴ではなく、発信の時間軸と転機
- **代表して読んでほしい記事**: 3本以内、選んだ理由を1文添える
- **外部**: GitHub、Qiita、Xなど

専用のProjectsページは作らない。今後、本当にまとまった個人制作物が増えたときだけ、`Projects` ではなく `作ったもの` や `実験` といったブログの語彙で追加を検討する。

## 2. 年表を装飾ではなく情報設計にする

現在の縦線と点は残す。ただし各記事へ同じ見た目の点を付けるだけでなく、年、日付、掲載元、更新状態をたどる索引にする。

### 推奨構造

```html
<section aria-labelledby="year-2026">
  <h2 id="year-2026">2026</h2>
  <ol>
    <li>
      <time datetime="2026-08-02">08.02</time>
      <article>...</article>
    </li>
  </ol>
</section>
```

### デスクトップ

- 左列: 年。十分な高さがあるときだけ `position: sticky`
- 中央: 縦線、月日、点
- 右列: 掲載元、題名、概要、タグ
- 点はクリック対象にせず、記事題名全体を明確なリンクにする

### モバイル

- 年は通常フローへ戻す
- 線と点は本文幅を圧迫しない細さにする
- 月日と掲載元を題名の上へ置く
- 概要は2〜3行で切るか、情報量が多い年は省略できるようにする

### 状態の表現

- 外部記事: 掲載元の文字と外部リンク記号。色だけで区別しない
- 更新記事: `更新 2026.08.02` を公開日と分ける
- 収録記事: 一覧では必要な場合だけ `このサイトへ収録` を小さく出す
- 人気記事: 並び替え時もPVや順位を表示しない。`よく読まれている` の印も初回は不要

## 3. AIテンプレート感は、色ではなく構造から減らす

ベージュ、セリフ、緑、角丸は、それ自体がAIらしいわけではない。問題は、文脈と関係なく頻出する構造が一式で揃うことである。

### 構造の禁止事項

- 中央揃えの巨大見出し + 説明 + CTA 2個
- 数値3個のステータスカード
- 同寸の3カードで特徴を説明
- すべてをBento Gridへ入れる
- `About / Skills / Projects / Contact` の定型順
- 実体のない `Featured Project`、`Impact`、`What I do`
- ページごとに同じ `eyebrow + 大見出し + カード群`

### 見た目の禁止事項

- 内容と無関係な紫〜青のグラデーション
- 意味のない発光、ぼかし球、ガラス面
- ほぼ全要素への大きな角丸と薄い影
- あらゆる語をピル型ラベルへ入れる
- 同じ線画アイコンをカードごとに置く
- Interなど単一の既定フォントだけで「モダン」を表す
- すべてのホバーで持ち上げ、拡大、バウンスする

### 文章の禁止事項

- `価値を提供する`、`課題を解決する` など、出来事のない抽象語
- `Selected Writings`、`Explore My Work` のような借り物の自己紹介語
- 数字の根拠がない成果アピール
- すべての節を同じ長さの3項目へ整えること
- 本文まで宣伝文に変えること

### 代わりに使うもの

- 実在する記事題名、日付、更新履歴
- その技術を選んだ理由や失敗
- 本人の短い余談
- 本人が撮った写真、手書きメモ、作成した図
- 年ごとの濃淡や空白
- 記事ごとに異なる長さを受け入れるレイアウト

## 4. 「人が作った感じ」は不便さではなく選択の痕跡で出す

壊れたレイアウト、読みにくいフォント、ランダムな傾きは本人らしさではない。次のような、小さく説明できる選択を積み重ねる。

- 年表の線と点をブログ共通のモチーフにする
- 題名に合わせて概要の長さが違ってもよい
- Aboutに現在読んでいるもの、試しているものを1項目だけ置く
- 代表記事には「今読むならここに注意」の編集注記を付ける
- コードブロックの色を自分のエディタに近づける
- 1つだけ本人所有の写真や図を使う
- 古い記事の語り口を均一化しすぎない

## 5. タイポグラフィを主なデザイン材料にする

カードや画像を減らす分、文字の大きさ、行間、字幅、罫線で階層を作る。

### 本文

- 初期候補: システム日本語サンセリフ
- サイズ: `clamp(1rem, 0.97rem + 0.15vw, 1.125rem)` 付近から実機比較
- 行高: 1.8〜2.0。記事一覧は1.55〜1.7
- 本文幅: 日本語32〜40字/行を出発点に、Mac、Windows、iPhoneで比較
- 段落間: 行高の0.9〜1.2倍を基準にする

### 見出し

- 大きさだけでなく、上下余白と罫線で段階を作る
- `text-wrap: balance` は短い見出しだけに使う
- 日本語の負のletter-spacingを強くしすぎない
- `font-feature-settings: "palt" 1` は見出しでだけ比較し、本文へ一括適用しない

### 書体の選択

初回実装はシステムフォントを基準にし、次のどちらかをA/B比較する。

1. 日本語はシステムフォント、欧文と数字だけ小さな表示書体を自己ホスト
2. 日本語表示書体を見出しだけ1ウェイトで自己ホスト

日本語Webフォントを全本文・多ウェイトで入れる案は、フォント転送量とCLSを測るまで採用しない。

## 6. 色は1つの役割に1つ使う

どの案でも色の役割を次へ固定する。

- `--color-ink`: 本文
- `--color-muted`: 日付、補助説明
- `--color-paper`: 背景
- `--color-rule`: 罫線
- `--color-accent`: リンク、年表の点、現在位置
- `--color-note`: 注記の背景。アクセントと兼用してもよい

アクセントは面積ではなく反復でブランドになる。ボタン、線、ピル、背景のすべてを同じ強色へしない。

配色を確定する前に、通常文字4.5:1以上、UI境界3:1以上を確認する。ダークモードは同時実装の必須条件にせず、ライトテーマを十分に仕上げた後で必要性を判断する。

## 7. カードは「別の物体」にだけ使う

同じページの続きである記事一覧、説明、タグを全部カードにしない。

カードを許可する例:

- 外部サイトの埋め込みプレビュー
- コード実行デモ
- 本文と意味的に独立した注意書き
- 写真や図版とキャプションの一組

カードを使わない例:

- 通常の記事行
- 3つのトピック説明
- Aboutの短い段落
- ヘッダーやフッターのリンク

区切りはまず余白、次に罫線、必要なときだけ背景差、最後にカードを検討する。

## 8. 動きは理解か位置関係を助けるときだけ使う

### 許可候補

- 検索・タグ絞り込み後の件数変化
- 目次の現在位置
- 外部リンクやコピー操作のフィードバック
- 記事内デモの状態変化

### 不採用候補

- 初回表示で記事行を順番に出す
- スクロールするだけで全見出しを出現させる
- 記事カードを常に浮かせる
- 背景を常時動かす
- ページ遷移のためだけに大きな要素を変形する

CSS Transitionで足りる範囲を基本とし、専用ライブラリは記事内デモが必要になったときに局所導入する。`prefers-reduced-motion` 時にも情報と状態が失われないことを必須にする。

## 9. 性能をデザイン仕様に含める

### 公開後の体験目標

- LCP: 2.5秒以下
- INP: 200ms以下
- CLS: 0.1以下
- 上記を75パーセンタイルで満たす

### 初回の実装予算

- ホームと記事一覧のための追加Client Component: 原則0
- デザイン専用アニメーションライブラリ: 0 KB
- ホームの初期表示画像: 原則0〜1枚
- 表示用Webフォント: 原則0〜1ファミリー、必要ウェイトのみ
- 記事画像: 明示的な寸法またはaspect-ratioを持つ
- 人気順データ: サーバー側でキャッシュし、PV値はクライアントへ渡さない

### 測定画面

- `/`
- `/writings`
- `/articles/blog-reboot-2026`
- 画像を持つ長文記事
- タグ一覧

デザイン前とデザイン後を、同じ端末条件、同じURLで比較する。

## 10. アクセシビリティを仕上げ工程へ回さない

### ワイヤー段階

- 見出し順を決める
- タイムラインを時系列の`ol`として読めるようにする
- ナビゲーションと検索を隠さない
- 色なしでも公開元と状態が分かるようにする

### コンポーネント段階

- `:focus-visible` を全操作へ持たせる
- 文字リンクを色だけでなく下線または明確な状態で示す
- タップ対象の大きさまたは間隔を確保する
- 外部リンクを新しいタブで開く場合は読み上げ説明を付ける

### 仕上げ段階

- 200%拡大
- キーボードのみ
- Reduce Motion
- 強制カラー
- 320px幅
- 日本語と長い英単語の混在
- 画像非表示
- JavaScript無効時の基本閲覧

## 11. 実装をテーマ変更しやすい構造にする

方向選択後、次の層を分ける。

```text
tokens.css       色、書体、余白、線、角丸、動き
global.css       リセット、本文、リンク、見出し
compositions.css stack、cluster、sidebar、timeline-layout
components.css   header、timeline-entry、search、article-note
utilities.css    visually-hidden、flow、measure
```

現在の単一`globals.css`を必ずこのファイル数へ分けるという意味ではない。少なくとも考え方を分け、将来の配色変更がコンポーネントごとの上書きにならない状態を目指す。

## 12. デザイン受入チェック

実装したスクリーンショットを見て、次をすべて確認する。

- 最初の画面で個人ブログだと分かる
- 最新記事の題名が自己紹介より目立つ
- 年表がページの主役になっている
- `Projects` がなくても何をしている人か分かる
- 3枚の同寸カードへ戻っていない
- 不要な英大文字ラベルがない
- 角丸、影、ピルの数を説明できる
- 写真や図は本人の内容と関係がある
- 長文記事の一行が広すぎない
- スクロール演出がなくても完成して見える
- 320px幅と200%拡大で横スクロールしない
- キーボードフォーカスが見える
- Webフォントと画像が遅れても本文位置が動かない
- 本人が半年後に記事を追加する手順が増えていない
