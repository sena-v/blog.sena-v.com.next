# 現在地とデザイン要件

調査日: 2026-08-02

## 内容の棚卸し

現在のサイトには、29本のローカル記事と8本の外部記事、合計37本の記録がある。公開年は2019年から2026年までにまたがる。

現在の主な画面は次の通り。

- `/`: 大きな紹介文、活動数値、3項目のトピック、選択記事、Aboutへの導線
- `/writings`: 検索、タグ、降順の縦型タイムライン
- `/articles/[slug]`: 記事見出し、日付、概要、タグ、本文
- `/tags/[tag]`: タグごとの記事
- `/about`: 書いている人、扱う領域、外部リンク
- `/privacy`: GA4を含むプライバシー情報

## 現在のよい部分

### 記事一覧の縦型タイムライン

縦線、点、日付、掲載元、題名、概要を一続きに見せる構成は、このブログで最も固有性がある。記事の多さをカードの枚数ではなく時間の蓄積として見せられる。

ユーザーからも、この年表表現を降順の記事目次として残したいという明確な希望がある。次期デザインでは補助パーツではなく、トップページと記事一覧の中心に昇格させる。

### 外部記事も同じ時間軸に置ける

Qiitaなどの外部記事は転載せず、元の公開日、掲載先、URL、収録日を保っている。サイト内記事と同じ一覧へ置く設計は、発信履歴の連続性を示せる。

### 改修の判断自体が記事になっている

`数年止まったNext.jsブログを、履歴を残して再構築した` は、成果物だけでなく、履歴を残した理由、基盤更新、URL設計、外部記事統合を説明している。独立したケーススタディページを作らなくても、技術的な判断を伝えられる。

### 基盤は軽い

Next.js App Router、Markdown、Server Component中心であり、大きなUIライブラリやアニメーションライブラリを使っていない。デザインのためだけにクライアントJavaScriptを増やさずに済む余地が大きい。

## 現在の違和感

### トップがSaaSのランディングページに近い

現在は次のパターンが一画面へ重なっている。

- 大きなヒーローコピー
- 丸いCTAボタン2個
- ステータス付きの数値パネル
- `01 / 02 / 03` の同寸カード
- 英大文字の小さなラベル
- `SELECTED WRITINGS` とカードグリッド

個々の要素は問題ないが、組み合わせるとブログより「サービス紹介」「転職用ポートフォリオ」「AI生成テンプレート」に近く見える。記事そのものへ到達するまでの説明も長い。

### 内容より容器の存在感が強い

白い面、枠線、角丸、影、ピル型ラベルが多く、ほぼすべての情報が何らかのコンテナへ入っている。記事の題名や日付よりカードの形が先に目に入る。

### ポートフォリオ向けの説明が前面に出ている

記事数、継続年数、外部投稿数は裏付けとしては有効だが、日常的に読むブログのトップで常時見せる必然性は弱い。転職時に説明したい情報と、通常の読者が読みたい情報を同じ優先度で置いている。

### 日本語サイトとして英語ラベルが多い

`TOPICS`、`SELECTED WRITINGS`、`ABOUT THIS BLOG` などの英大文字ラベルは、階層を作る便利な記号ではある。一方、反復するとテンプレートのセクション構成に見えやすい。固有名詞以外は日本語を基本にし、英語はナビゲーションやメタデータへ限定する方が自然である。

## 変えない要件

1. メインは個人ブログである。
2. ポートフォリオ性は副次的に持たせる。
3. 記事一覧は公開日の降順を標準にする。
4. 縦線と点を使う年表表現を残し、さらに活かす。
5. 独立した `Projects` ページを主役にしない。
6. 「課題と方針」の年表は通常の記事内に残す。
7. 外部記事の初出日を変えない。
8. PVの実数は公開しない。
9. 長文記事の読みやすさと表示性能を、装飾より優先する。
10. 過去の更新停止を消さず、再開した履歴として扱う。

## 読者と優先タスク

### 通常の読者

- 新しい記事を見つける。
- 特定の技術や題名を検索する。
- 過去の記事を年やタグからたどる。
- 記事本文を落ち着いて読む。

### 転職時に訪れる読者

- 何に関心がある人かを短時間でつかむ。
- 最近の技術選定や改修理由を読む。
- 過去から現在までの変化を見る。
- GitHub、Qiita、Aboutへ進む。

両者を分けた専用トップは作らない。通常の読書動線を崩さず、Aboutと代表記事が後者の追加情報を担う。

## 次期デザインで最初に変える情報の順番

トップページの優先順位を次へ変える。

1. サイト名と短い自己紹介
2. 最新記事を含む降順タイムライン
3. 年、タグ、検索への入口
4. 今読んでほしい記事を2〜3本だけ注記
5. Aboutと外部リンク

数値パネル、3分割トピックカード、大型CTAは削除候補とする。必要な内容はAboutやタイムライン周辺の短い文へ戻す。

## デザインの評価軸

各案を次の6項目、各5点で評価する。

1. 個人ブログとして自然か
2. 年表を主役にできるか
3. 本人らしさを育てられるか
4. 長文を読みやすくできるか
5. 表示性能とアクセシビリティを守れるか
6. 一人で保守しやすいか

見た瞬間の派手さは独立した評価項目にしない。半年後も記事を追加しやすく、数年後にも再設計しやすいことを重視する。
