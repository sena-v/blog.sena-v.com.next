# 本人素材を編集する20の方向

## A. 写真の編集

### 01. 黒台紙のセレクト / Dark Select


- 構造: 3×3の写真、連番、左の最新記事3件。第3回10をさらに写真編集の道具として整理する。
- 必要素材: 同じ時期に本人が撮った6〜9枚と、各写真の一行メモ。
- 固有性: 日常の対象の選び方と、採用・不採用の印が本人性になる。
- 実装: CSS Grid。最初の3枚以外はlazy-load。モバイルは2列。
- 注意: 暗色テーマそのものを採用理由にしない。毎回9枚を必須にしない。

### 02. 白い校正刷り / White Proof Sheet


- 構造: 白地の4×3小画像、赤い選択印、下部の静かな記事目次。
- 必要素材: 12枚程度の同一シリーズ。公開する画像だけ高解像度で持つ。
- 固有性: 何を選ばなかったかも薄く残り、編集判断が読める。
- 実装: サムネイル用の小さい派生画像を生成。選択印はSVGではなくHTMLの記号でもよい。
- 注意: フィルムの穴やメーカー表記を装飾として追加しない。

### 03. 横長フィルム / Horizontal Sequence


- 構造: 5枚の横一列の連作を画面中央に置き、上下は余白と記事一覧だけにする。
- 必要素材: 左から右に視線や時間が進む5枚。
- 固有性: 一枚のヒーロー写真では出せない、観察の移動が見える。
- 実装: デスクトップは5列、モバイルは横スクロールではなく縦の5枚に戻す。
- 注意: カルーセルにせず、全体の順序を一目で見せる。

### 04. 縦のフレーム列 / Vertical Frame Rail


- 構造: 左端に細い縦写真6枚、中央にキャプション、右に記事一覧。
- 必要素材: 縦位置で切り取っても主題が残る写真。
- 固有性: 写真と文章が上下へ同時に進み、フィードより編集紙面に近い。
- 実装: Gridの3列。モバイルは`写真→キャプション→記事`の組を順番に並べる。
- 注意: 縦写真を装飾帯にせず、各キャプションへ意味を持たせる。

### 05. 二枚組の対話 / Diptych Journal


- 構造: 関係する二枚を大きく対置し、その間または下に一記事と短い注記を置く。
- 必要素材: 似ている／反対である理由を説明できる二枚。
- 固有性: 写真の「組み合わせ」が一つの考えになる。
- 実装: `figure`二つと記事リンク。毎回のトップではなく特集時だけ差し替える。
- 注意: 写真だけで意味を完結させず、短い本人の言葉を添える。

## B. 観察の索引

### 06. 一日の三場面 / Three Times of Day


- 構造: 朝、昼、夜の三枚と時刻。右下に最近の記事3件。
- 必要素材: 同じ日または同じ場所の時間差が分かる写真。
- 固有性: 経歴ではなく、普段の観察のリズムが自己紹介になる。
- 実装: 3列からモバイル1列へ。正確な位置情報は出さない。
- 注意: 毎日の更新を要求する日記UIにはしない。

### 07. 道具の索引 / Object Index


- 構造: キーボード、ノート、ケーブルなどを一枚の俯瞰写真に収め、番号と凡例で記事へ結ぶ。
- 必要素材: 実際に使う5〜7個の物と、各物に対応する話題。
- 固有性: 抽象的なSkillsではなく、使っている物から仕事や関心が見える。
- 実装: 写真上にクリック領域を置かず、横のHTML凡例をリンクにする。
- 注意: 商品紹介やデスクツアーに寄せすぎない。

### 08. 一枚の切り取り研究 / Crop Study


- 構造: 一枚の写真を全景、縦、正方形、細部の4通りで見せ、右に選択理由を書く。
- 必要素材: 切り取りで意味が変わる本人写真一枚。
- 固有性: 完成画像より「どう見るか」を主題にできる。
- 実装: 同一元画像の`object-position`ではなく、必要なら用途別画像を事前生成する。
- 注意: 無意味なレスポンシブ切り替えではなく、各クロップの役割を記録する。

### 09. 季節のフィールドノート / Seasonal Field Notes


- 構造: 四季または四半期の4枚、短い観察文、最近の記事。
- 必要素材: 長期にわたり本人が撮った4枚。年は大きく見せない。
- 固有性: 更新停止期間を隠さず、時間の蓄積を生活側から扱える。
- 実装: 画像4枚は固定し、記事一覧だけ自動更新する半固定ホーム。
- 注意: 季節ごとの更新義務にしない。年表UIへ戻さない。

### 10. 通り道の六場面 / Six Frames on the Way


- 構造: 移動の順に6枚を並べ、終点の横に記事一覧を置く。
- 必要素材: 生活圏を特定させない範囲の道、車窓、足元、光など。
- 固有性: 写真の被写体より、目がどこで止まったかが本人らしさになる。
- 実装: DOM順も移動順。地図やGPSは持たない。
- 注意: 自宅・勤務先・行動時間を推測できる連続情報は省く。

## C. 制作過程

### 11. 見開きノート / Notebook Spread


- 構造: 一冊の見開きを大きく置き、右に注記と関連記事3件。第3回11を一素材へ絞る。
- 必要素材: 公開してよい実際のノート一見開き。
- 固有性: 文字の癖、消し跡、余白の使い方がそのまま残る。
- 実装: 画像の文字を本文扱いせず、要点をHTMLの注記にも書く。
- 注意: 読めない生成文字を使わない。機密部分は撮影前に隠す。

### 12. 三段階の推敲 / Revision Proof


- 構造: 下書き、赤入れ、公開版の三段階を左から右へ並べ、一記事へ収束させる。
- 必要素材: 同じ文章または画面の三状態。
- 固有性: 完成度を主張せず、考えを変えた箇所を見せられる。
- 実装: 各段階を`figure`にし、差分説明はHTML。モバイルは時系列の縦順。
- 注意: 内容のない赤線を演出で加えない。

### 13. ばらの資料束 / Loose Leaf Set


- 構造: 寸法の違う4枚の紙を整った基準線へ置き、各紙に一つの記事を対応させる。
- 必要素材: メモ、印刷したコード、構成案、図など四種。
- 固有性: 異なる考え方の道具を一つの作業面で見せられる。
- 実装: 影で紙を表現せず、余白と細い輪郭で分ける。
- 注意: 傾きは一枚まで。コラージュ演出より可読性を優先する。

### 14. 余白の赤入れ / Margin Edits


- 構造: 通常の記事一覧の左右余白に、本人の短い手書き印とHTML注記だけを置く。
- 必要素材: 丸、矢印、短語など本人が実際に使う少数の筆跡。
- 固有性: 画像を主役にせず、一覧自体へ編集者の声を足せる。
- 実装: 筆跡は小さな透過画像またはSVG。意味は隣のHTMLにも残す。
- 注意: 全記事へ赤入れしない。3箇所以内。

### 15. 図と凡例 / Diagram and Legend


- 構造: 一枚の手描き構成図を左、番号付き凡例と関連記事を右に置く。
- 必要素材: 実際の設計や調査で作った図一枚。
- 固有性: スキル名の列挙ではなく、要素同士をどう捉えたかが伝わる。
- 実装: 複雑図には短いaltと、同等情報を持つHTML凡例を用意する。
- 注意: 図の内容が古くなった場合は日付と文脈を明記する。

## D. 混成資料

### 16. コードと紙の二枚組 / Code and Paper


- 構造: 左にコードの実画面、右に対応するノート。下に一記事と判断の要約。
- 必要素材: 同じ実装を示すコードと紙の一組。
- 固有性: 実装だけでも思考だけでもない往復が見える。
- 実装: コードは画像だけでなく抜粋テキストも記事側に持つ。秘密情報を確認する。
- 注意: IDE全画面をそのまま貼らず、判断に関係する箇所へ切る。

### 17. 一記事の材料箱 / Article Evidence Pack


- 構造: `package.json`、ターミナル、ノート、変更前画面の4資料が中央の一記事へつながる。
- 必要素材: 一つの記事を支える異なる形式の資料4点。
- 固有性: ケーススタディページを作らず、記事の根拠をホームで少しだけ見せる。
- 実装: 資料はサムネイル、詳しい説明は記事本文。線で無理に接続しない。
- 注意: ポートフォリオの成果物展示へ寄せず、記事を入口に保つ。

### 18. 画面の校正 / Screen Proofs


- 構造: デスクトップとモバイルの実画面を二枚、実際の確認メモを横へ置く。
- 必要素材: 自サイトの画面と、本当に行ったQA項目。
- 固有性: デバイスモックアップより、直した箇所と検証の跡が見える。
- 実装: ブラウザー枠を画像へ合成せず、figureとcaptionでサイズを記録する。
- 注意: 架空の「改善率」やLighthouse満点を載せない。

### 19. 外部記事の切り抜き / External Writing Clippings


- 構造: Qiitaなど外部記事の題名部分を小さく引用し、初出日、掲載先、自分の紹介文、リンクを縦に並べる。
- 必要素材: 公開済み外部記事のURL、正確な初出日、短い自分のコメント。
- 固有性: 発信履歴を転載せず、現在のブログへ編集して集められる。
- 実装: 情報の本体はHTML。スクリーンショットは補助で、サイト変更時もリンクが残る。
- 注意: 記事全文や第三者画像を複製しない。リンク切れチェックを入れる。

### 20. 一週間の作業台 / Weekly Worktable


- 構造: 写真、図、コード、短いメモ、公開画面の5断片を安定したグリッドへ置き、右端に記事一覧。
- 必要素材: 同じ一週間または同じテーマから出た5点。
- 固有性: 第3回10の観察と11の制作過程を、演出せず一面に同居させる。
- 実装: 素材型ごとの小さなMDXコンポーネントを用意し、順序はfrontmatterで編集する。
- 注意: 最も更新負荷が高い。常設ホームより、月一回の「今月の机上」に向く。
