# 選び方と次の作業

## 現時点の見立て

第3回10と11のどちらかをそのまま採用するより、まず次の5案を見ると好みの境界が分かりやすい。

1. **02 白い校正刷り** — 10の編集感を残し、暗色と3×3構図への依存を外す。
2. **07 道具の索引** — 写真を作品としてではなく、関心への入口にする。
3. **12 三段階の推敲** — 11の「考えた跡」を一記事の変化として明瞭にする。
4. **16 コードと紙の二枚組** — 観察と実装、ブログとポートフォリオの中間を最小構成で作る。
5. **20 一週間の作業台** — 10と11を本当に混ぜた場合の上限を確認する。

これは最終候補の順位ではない。密度、素材の種類、更新負荷が異なる比較用の5点である。

## 選ぶときの質問

各画像に対して「好き／嫌い」だけでなく、次を一語でも残す。

- 写真の密度は多すぎるか、足りないか。
- 黒い台紙と白い紙面のどちらが内容に合うか。
- 日常の写真と制作途中の資料のどちらを自分のブログに置きやすいか。
- 素材と記事を一対一で結ぶ必要があるか。
- 月一回なら準備できる素材量か。
- スマートフォンで通常の縦一覧へ戻っても魅力が残るか。

## 画像を見た後の実装手順

### 1. 素材監査

本人素材を公開せずに、種類と枚数だけ数える。

```text
写真の連作          6〜12枚の組が何組あるか
ノート・構成案      公開可能な見開きが何点あるか
コード・画面        機密を含まない実例が何点あるか
外部記事            URL、初出日、掲載先が揃うか
```

素材が存在しない案を、生成素材で埋めて採用しない。

### 2. 役割の違う3案をlocalhostで組む

画像では文字の折り返し、リンク操作、モバイル、読み込み量が分からない。好みが分かった後、写真系1案、紙系1案、混成1案を実記事と仮の本人素材でHTML化する。ルートは本番ナビに出さない比較用URLにする。

### 3. 性能と保守を比較する

- 画像数、転送量、LCP、CLS
- 素材がない記事のフォールバック
- 画像なしでも記事へ到達できるか
- alt、caption、キーボード操作
- 一回の更新で必要な編集時間

### 4. 本番仕様を一段弱くする

コンセプト画像は違いを見せるため強く作っている。本実装では、選んだ案の素材量または注記量を一段減らし、記事を読む場所を主役に戻す。特集表示と通常表示を分ける方法も残す。

## 推奨する運用形

常設ホームを毎回作り込むより、次の二層が続けやすい。

- 通常時: 静かな最新記事一覧 + 本人素材1〜2点
- 素材が揃った時: 連作または制作資料を使う小さな特集面

これなら更新のたびに撮影やスキャンを要求せず、良い素材がある記事だけ固有の見せ方を持てる。
