# 20のデザイン方向

## A. 読むための編集設計

### 01. 本の余白 / Book Margin


- 構造: 760px前後の本文列。最新1件に導入を付け、ほか3件は題名だけ。右側に日付と短い編集注を傍注として置く。
- 造形: 生成り、墨、暗い朱。本文は日本語明朝、UIはサンセリフ。罫線は脚注だけ。
- モデル: [Robin Sloan](https://www.robinsloan.com/)、[Jason Santa Maria](https://jasonsantamaria.com/)。
- 実装: CSS Gridで本文列と傍注列。モバイルでは傍注を題名直下へ移す。Client Component不要。
- 強み: 個人ブログとして最も自然で、長文記事まで一貫する。
- リスク: 書体選定が弱いと単に古い文芸サイトに見える。日本語Webフォントの容量を要検証。

### 02. 新聞机 / Newspaper Desk


- 構造: 上部にサイト名と日付、下は主記事1段 + 短文2段。記事種別を紙面上で混ぜる。
- 造形: 細い罫線、段組、大小の見出し。カード背景や角丸は使わない。
- モデル: [kottke.org](https://kottke.org/)、[Simon Willison](https://simonwillison.net/)。
- 実装: CSS Grid。記事の長さでgrid spanを決める小さな表示規則をサーバー側に持つ。
- 強み: 外部記事と自サイト記事を一つの発行物として扱える。
- リスク: 更新量が少ないと紙面が空く。ホームは5件固定とし、不足分を古い記事で埋めない。

### 03. 一冊の表紙 / Single Cover


- 構造: 最新記事の題名をホームの大半に使い、下辺にほか3件の小さな目次。
- 造形: 写真なし。題名の改行と余白だけで表紙を作る。号数の代わりに公開日を小さく置く。
- モデル: [Frank Chimero](https://frankchimero.com/)、[Elliot Jay Stocks](https://elliotjaystocks.com/)。
- 実装: 最新記事を静的取得。タイトルの文字数別に2〜3段階の`clamp()`を用意する。
- 強み: 新しい記事を書いたこと自体がサイトの更新になる。
- リスク: 更新停止が最も見えやすい。日付を隠さず、Aboutへの静かな導線を置く。

### 04. 脚注ジャーナル / Marginalia Journal


- 構造: 最新記事の導入2段落をそのまま見せ、欄外に関連リンク、更新日、外部記事を注釈として置く。
- 造形: 本文と細いリーダー線、等幅の注釈。装飾図は一つまで。
- モデル: [Maggie Appleton](https://maggieappleton.com/)、[Aresluna](https://aresluna.org/)。
- 実装: CSS Gridと`aside`。モバイルでは本文中の自然な位置へ順番を変えずに挿入。
- 強み: ポートフォリオ情報を自己紹介カードではなく、記事の文脈として見せられる。
- リスク: 注釈が増えると本文より強くなる。ホームの欄外項目は3つまで。

## B. 探すためのアーカイブ設計

### 05. 編集索引 / Editorial Index


- 構造: 日付、題名、種類、タグを一行で見渡す。ホームは最新8件の短い索引、全件は検索付き。
- 造形: 表計算ではなく美術館の収蔵品目録。太い見出しと細い行罫線、広い左右余白。
- モデル: [Laurel Schwulst](https://laurelschwulst.com/e/)、[Aresluna](https://aresluna.org/)。
- 実装: セマンティックなリストまたはテーブル。モバイルは題名を一段、メタ情報を二段目へ折り返す。
- 強み: 37件と外部記事を最も明瞭に扱え、後の人気順も自然に追加できる。
- リスク: ユーティリティに寄りすぎる。見出し書体と行間で編集感を作る。

### 06. 関心の星座 / Topic Constellation


- 構造: `Webの基礎`、`作業環境`、`振り返り`など本人の関心を空間的な3群に分け、各群に2記事。
- 造形: 円形ノード図ではなく、紙面上の距離と文字サイズで近さを示す。接続線は使わない。
- モデル: [Maggie Appleton](https://maggieappleton.com/)、[Jim Nielsen](https://www.jim-nielsen.com/)。
- 実装: CSS Grid Areas。タグから自動生成せず、ホーム用の3群だけ編集設定で管理。
- 強み: 何を書く人かが自然に伝わり、ポートフォリオの側面を記事から作れる。
- リスク: 抽象カテゴリ名はAI臭くなる。実際の記事題名を読んで本人の言葉で命名する。

### 07. 書棚 / Library Shelves


- 構造: 3本の縦長の棚に代表記事を置き、最上段だけ最新記事。全件は別画面。
- 造形: カードではなく、本の背のような縦の罫線と題名。色面は棚ごとに変えない。
- モデル: [Aresluna](https://aresluna.org/)、[Craig Mod](https://craigmod.com/)。
- 実装: CSS Grid。モバイルでは棚を縦積みし、各棚の見出しをstickyにしない。
- 強み: 記事数が増えてもトップの密度を固定できる。
- リスク: 比喩を強くしすぎるとテーマサイトになる。書棚イラストは使わない。

### 08. 検索から始める / Search First


- 構造: 大きな検索欄、最近の記事3件、よく使う検索語ではなく3つの具体的な入口。
- 造形: 検索UIを中央に一つ。結果は通常の行リストで、タグピルを並べない。
- モデル: [Simon Willison](https://simonwillison.net/)、[Steph Ango](https://stephango.com/)。
- 実装: 既存の`query`パラメーターとサーバー側絞り込みを再利用。JavaScriptなしでも送信可能にする。
- 強み: 過去37件を実用的な資産として見せる。
- リスク: 初訪問で何を書いているか分かりにくい。検索下に最新3件を必ず残す。

## C. 画像と物質感の設計

### 09. 一枚の写真 / Photo Anchor


- 構造: 第2回06の発展形。本人撮影の一枚と、紹介2文、最新3件の二分割。
- 造形: 写真側が色を担い、UI側はほぼ白黒。写真の縦横比を先に固定しない。
- モデル: [Craig Mod](https://craigmod.com/)、[Paul Stamatiou](https://paulstamatiou.com/)。
- 実装: `next/image`、`sizes`、明示寸法。モバイルは写真を本文の後ろへ置く版も比較。
- 強み: すでに好感触だった静けさを保ちつつ、本人素材で固有性を作れる。
- リスク: 借り物・生成写真では逆にAIっぽくなる。本実装は本人素材が条件。

### 10. コンタクトシート / Contact Sheet


- 構造: 6〜9枚の小さな本人写真に、記事題名を一つずつ対応させる。最新3件は上部に別表示。
- 造形: 写真ラボのベタ焼きのような連番と狭い間隔。影、テープ、ポラロイド枠は使わない。
- モデル: [Paul Stamatiou](https://paulstamatiou.com/)、[Ohara Daijiro](https://oharadaijiro.com/)。
- 実装: CSS Grid、`next/image`、下方画像のみlazy-load。altを記事題名の重複にしない。
- 強み: 記事以外の生活・制作の蓄積が見え、個人サイトらしい。
- リスク: 素材準備と画像重量が大きい。画像が揃うまで候補に上げない。

### 11. 机上のノート / Working Notes


- 構造: 実際のメモ、構成案、図を2〜3点置き、横に関連する記事リンクと短い注記。
- 造形: 生成した手書き風ではなく、本物の筆跡・紙・スクリーンショットをトリミングして使う。
- モデル: [Austin Kleon](https://austinkleon.com/)、[Maggie Appleton](https://maggieappleton.com/)。
- 実装: 画像は静的import。注記はHTMLテキストにし、画像へ焼き込まない。
- 強み: AI脱臭に最も直接効く。完成品より考えた跡を見せられる。
- リスク: 読めないメモや機密情報を出さない。素材の選別が必要。

### 12. ビジュアルエッセイ / Visual Essay


- 構造: 最新の長文記事を大判図版、題名、導入で特集し、横に小さな記事目次。
- 造形: 雑誌の扉ページ。図版は記事固有で、全記事にサムネイルを要求しない。
- モデル: [Craig Mod](https://craigmod.com/)、[Paul Stamatiou](https://paulstamatiou.com/)。
- 実装: frontmatterに任意の`featuredImage`と焦点位置。画像なし時は03へフォールバック。
- 強み: ブログ改善記事や技術検証を、内容に即した図版込みで強く見せられる。
- リスク: 毎回アートディレクションすると更新が重くなる。四半期に一記事程度。

## D. 文字とグラフィックの設計

### 13. 日本語ポスター / Japanese Poster


- 構造: 最新3件の題名を大きな日本語の面として非対称に配置。日付と説明は小さく端へ置く。
- 造形: 生成り、黒、鮮やかな一色。角丸、影、グラデーションなし。
- モデル: [Shunsuke Kudo](https://shunsukekudo.com/)、[Ohara Daijiro](https://oharadaijiro.com/)。
- 実装: CSS Gridと`clamp()`。タイトル長別の改行候補をHTMLの`<wbr>`で編集可能にする。
- 強み: 画像なしでも明確に「デザインされた」印象を作れ、日本語ブログに固有。
- リスク: 題名の可読性を造形のために壊さない。モバイルでは通常の縦順へ戻す。

### 14. 書体標本 / Type Specimen


- 構造: 記事題名を異なるサイズ・ウェイトの標本行として表示し、日付を基準線上に揃える。
- 造形: 一つの可変サンセリフ + 日本語システムフォント。英数字だけ幅やウェイトを動かす。
- モデル: [Elliot Jay Stocks](https://elliotjaystocks.com/)、[Jason Santa Maria](https://jasonsantamaria.com/)。
- 実装: variable font 1ファイルをsubset。hover変化は装飾で、通常状態でも情報を読めるようにする。
- 強み: 写真なしで高い仕上がりを狙え、記事題名が作品になる。
- リスク: 日本語と欧文の品質差が出る。フォントロードとCLSを測定する。

### 15. モノクロZINE / Monochrome Zine


- 構造: 最新記事、短いメモ、外部記事を太い帯と細い欄で交互に置く。
- 造形: 白黒、高コントラスト、1点の粗い白黒画像。偽の紙ノイズは使わない。
- モデル: [Lynn Fisher](https://lynnandtonic.com/)、[SHONEN-B](https://www.koji-ka.com/)。
- 実装: HTML順は通常のフィード、CSSだけで帯の幅を変える。画像filterは事前処理。
- 強み: 静かな案とは明確に違い、個人発行物の勢いが出る。
- リスク: 長文の読書画面まで同じ強度にしない。記事ページは落ち着かせる。

### 16. 色面編集 / Color Field


- 構造: 3つの話題を大小の色面にし、各面に代表記事1件。最新記事は白地に独立。
- 造形: 3色以内、面積比を不均等にする。グラデーション、ガラス、影なし。
- モデル: [SANOGRAPHIX](https://sanographix.github.io/)、[Lynn Fisher](https://lynnandtonic.com/)。
- 実装: CSS Custom PropertiesとGrid Areas。色を外しても見出し順で意味が通るDOM。
- 強み: カードUIと違う方法で話題の違いを視覚化できる。
- リスク: 色面を均等にするとテンプレート感が戻る。3つの内容量を意図的に変える。

## E. 個人Webと遊びの設計

### 17. 素のWeb / Native Web


- 構造: サイト名、短い自己紹介、最新記事、全記事、About、RSS。ほぼ文書そのもの。
- 造形: ブラウザー既定に近い青リンクと下線。ただし行長、余白、フォーカスは丁寧に調整。
- モデル: [Adactio](https://adactio.com/)、[Steph Ango](https://stephango.com/)。
- 実装: 最小CSS、Server Component、画像なし。ベースライン案として全候補と比較する。
- 強み: 最速・最も保守しやすく、AIテンプレート要素が入り込む余地が少ない。
- リスク: 意図が伝わらないと未完成に見える。コピーと文字組みの精度が必要。

### 18. 小さな遊び場 / One Handmade Detail


- 構造: 通常の最新記事一覧に、本人の関心を表す小さなCSS造形を一つだけ置く。
- 造形: 例はキーボードのキー、ウィンドウ、犬など。既製3D絵文字や抽象球体は使わない。
- モデル: [Takuya Matsuyama](https://www.craftz.dog/)、[Lynn Fisher](https://lynnandtonic.com/)。
- 実装: CSSまたは小さなSVG。JavaScriptを使う場合も50行程度、reduced motionでは静止。
- 強み: ブログの読みやすさを壊さず、覚えてもらえる一点を作れる。
- リスク: モチーフは本人が決める必要がある。先に仮のマスコットを生成しない。

### 19. 編集デスク / Editorial Desk


- 構造: 左に最新記事、中央に短いメモ、右に外部記事。3つの縦ペインを同時表示。
- 造形: OSのウィンドウ模倣ではなく、細い罫線と異なる列幅だけで作業机を示す。
- モデル: [Jim Nielsen](https://www.jim-nielsen.com/)、[Simon Willison](https://simonwillison.net/)。
- 実装: CSS Grid。モバイルは`最新 → メモ → 外部`の順に縦積み。独立スクロールは使わない。
- 強み: 外部で書いた記事を自サイトの活動と自然に並べられる。
- リスク: 各列の更新頻度が違うと空く。中央・右は最大3件で古い日付を隠さない。

### 20. 季節号 / Seasonal Edition


- 構造: 情報設計は安定した一段組のまま、四半期ごとに表紙色・一枚の本人素材・短い近況だけ変更。
- 造形: `2026 夏`のような静かな号表示。全面リニューアルではなく、可変部分を限定する。
- モデル: [Lynn Fisher](https://lynnandtonic.com/)、[Laurel Schwulst](https://laurelschwulst.com/home/)。
- 実装: テーマトークンと任意の`edition`データ。過去テーマもGit履歴か小さなarchiveで残す。
- 強み: 継続的な手入れが自然に見え、ブログ更新のきっかけになる。
- リスク: 更新義務になると逆効果。未更新時は前号のままで問題ない文言にする。
