# 調査条件とバリエーション規則

## 修正した前提

第2回の06「一枚の写真」が比較的よかったことは、写真分割レイアウトを採用する根拠ではない。良かった可能性が高いのは、次の三点である。

1. 一画面の要素数が少ない。
2. 左右の役割が明快で、読む順序に迷いにくい。
3. 小さなカードを均等に並べず、一つの面と文字だけで構成している。

第3回はこの三点を品質基準に残しつつ、写真の有無、左右分割、白い背景には固定しない。

## 「別案」と数える条件

次の5軸のうち、最低2軸が変わる場合だけ別案と数える。

| 軸 | 選択肢の例 |
| --- | --- |
| ホームの主役 | 最新記事、記事群、検索、話題、本人素材、文字そのもの |
| 一覧構造 | 一段、新聞段組、表、棚、空間配置、連続フィード |
| 文字の性格 | 本文書体中心、巨大見出し、等幅、明朝、可変書体、素のHTML |
| メディアの役割 | なし、一枚、複数、スキャン、図解、CSS造形 |
| 操作 | 通常リンク、検索優先、フィルタ、季節切替、軽い探索 |

色、角丸、写真の被写体、左右反転だけの違いは別案に数えない。

## 20案の配分

- 読むための編集設計: 4案
- 探すためのアーカイブ設計: 4案
- 画像と物質感の設計: 4案
- 文字とグラフィックの設計: 4案
- 個人Webと遊びの設計: 4案

写真を主役にするのは09〜12の4案だが、09だけが第2回06の直接的な発展形である。10は複数写真の索引、11は本人の紙資料、12は記事単位のビジュアルエッセイで、情報設計が異なる。

## 全案に共通する制約

- まずブログであると分かる。
- ホームの最新記事は原則3〜6件。全37件は`/writings`へ送る。
- 年別の縦線・点・年表をホームの基本構造にしない。
- Projects、Skills、実績数値、採用向けCTAをトップへ常設しない。
- 文章、写真、図版のない空疎な「映える面」を作らない。
- 320px相当の表示幅で横スクロールを要求しない。
- 色だけでリンクや状態を区別しない。
- 装飾のためのクライアントJavaScriptを標準にしない。

## 「デザイナーが作った感」の定義

豪華さやアニメーション量ではなく、次の判断が一貫している状態を指す。

- 何を見せないかが決まっている。
- 余白、罫線、書体、画像に同じ編集意図がある。
- 記事の長さやタイトルが変わっても破綻しない。
- モバイルが縮小版ではなく、自然な読み順に再構成される。
- 既製コンポーネントの寄せ集めではなく、本人の文章と素材が画面を決める。
- 派手な特徴がなくても、リンク、日付、段落の細部に手入れがある。
