# 推奨と次の選び方

## いま一案へ絞らない

第2回は静かな案に寄せた結果、比較画像の差が小さくなった。第3回では、平均点の高い一案を機械的に採用せず、次の4案を「役割の違う比較対象」として残す。

1. 01「本の余白」: 長文ブログとしての完成度を見る基準。
2. 05「編集索引」: 過去37件と将来の人気順を扱う基準。
3. 13「日本語ポスター」: デザイナーが組んだ印象を画像なしで作れるかを見る基準。
4. 09「一枚の写真」: 第2回06で感じた静けさを、本人素材で再確認する基準。

この4案は似た案の上位4つではない。読書、探索、グラフィック、写真という別の評価軸を代表する。

## 20枚を見るときの質問

「好きな番号」を一つ選ぶより、次を分けて記録する。

1. 最初に読みたくなる構造はどれか。
2. 文字の強さはどこまで許容できるか。
3. 一画面に見えてよい記事数は何件か。
4. 写真・紙・イラストのうち、実際に自分で用意し続けられるものは何か。
5. 外部記事は最新記事と同列か、別欄か。
6. 「これは自分のブログではない」と感じる案はどれか。その理由は営業感、アート感、密度、色、動きのどれか。

この回答から、別案同士の一部を混ぜる。ただし「01の文字 + 05の索引 + 13の表紙」のように役割ごとに限定し、画面要素を足し合わせない。

## localhostへ進める工程

### Step 1 — 20枚から反応を取る

- `好き`を最大5案
- `嫌い`を最大5案
- 好きな理由と嫌いな理由を各一言
- 素材を用意できる案に印を付ける

### Step 2 — 3案へ絞る

最低限、静かな案、索引案、グラフィック案を1つずつ残す。写真案は本人素材の候補がある場合だけ3案へ含める。

### Step 3 — 同じ実データでHTML化

3案すべてに、同じ記事題名、日付、外部記事、About文を入れる。画像モックアップの雰囲気ではなく、長い日本語題名が折り返す実画面を比較する。

### Step 4 — 1440 / 390 / 320pxで確認

- 1440px: 構図と密度
- 390px: 通常のスマートフォン
- 320px: Reflowと長い日本語題名
- 200%ズーム: 文字と固定要素の破綻
- キーボード: フォーカス順と見た目

### Step 5 — 一案を選んで視覚言語を詰める

選定後に初めて、書体2案、配色3案、罫線、リンク、画像クロップ、動きを比較する。構造と色を同時に決めない。

## 実装上の共通ベストプラクティス

### レスポンシブ

[WCAG 2.2 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)に合わせ、320 CSS px相当で記事本文やナビゲーションに二方向スクロールを要求しない。複雑なデスクトップ構図も、モバイルではDOMの自然な順序へ戻す。

### 画像

- 画像案では`next/image`に寸法と`sizes`を与え、レイアウトシフトを避ける。
- 最初の画面内にあるLCP候補だけを優先し、画面外の画像は遅延読込する。
- 複数画像案は、モバイルへデスクトップ幅の画像を送らない。
- 写真の意味がクロップで変わる場合は`picture`相当のart directionを検討する。

参照: [Next.js production checklist](https://nextjs.org/docs/app/guides/production-checklist)、[web.dev: responsive images](https://web.dev/articles/serve-responsive-images)、[web.dev: browser-level lazy loading](https://web.dev/articles/browser-level-image-lazy-loading)

### 書体

- 本文全体の日本語Webフォントは、効果が容量を上回る場合だけ採用する。
- 表示書体は見出し限定、英数字フォントはsubsetを優先する。
- フォールバックとの字幅差を確認し、`font-display`と読み込み順を決める。
- 文字間隔をユーザーが変更しても内容が欠けない。

参照: [web.dev: Optimize WebFont loading](https://web.dev/articles/optimize-webfont-loading)、[WCAG 2.2 Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)

### 動き

- 動きは18の一点、14の補助的な文字変化など、意味のある箇所だけ。
- 本文の出現アニメーション、常時浮遊、スクロール連動の装飾は標準にしない。
- `prefers-reduced-motion`では動かさず、情報を失わない。

参照: [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)

### 色とフォーカス

- コントラストを測る。
- 通常リンクの下線または同等の非色彩手掛かりを残す。
- `:focus-visible`をhoverより先に設計する。

参照: [WCAG 2.2 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[WCAG 2.2 Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

## AIっぽさを避ける具体策

- 20案のどれでも、`CONTEXT`、`SELECTED WORKS`、`STATUS/ACTIVE`のような英大文字ラベルを装飾目的で移植しない。
- 写真は本人撮影、紙片は本人の実物、図は記事内容から作る。生成素材を本番の人格代わりにしない。
- 3つの均等カード、均等な文章量、同じ角丸を「整っている」理由だけで使わない。
- 「技術とデザインの交差点」「よりよい体験を探求」のような汎用自己紹介を置かない。
- 失敗、保留、具体的な比較条件を文章に残す。
- 既存記事の癖を消さず、新規UI文言だけ本人の普段の日本語へ寄せる。
