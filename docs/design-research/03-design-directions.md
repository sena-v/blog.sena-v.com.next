# デザイン方向案の比較

調査日: 2026-08-02

この資料は、流行の見た目を五つ並べたものではない。すべて同じ記事データ、同じ降順の時間軸、同じURL構造で実装でき、後から配色や文字組みだけを変更しやすい案に限定した。

## 比較結果

各項目は5点満点。評価軸の定義は [00-current-audit.md](./00-current-audit.md) に記載している。

| 案 | ブログらしさ | 年表との相性 | 本人らしさ | 長文 | 性能・A11y | 保守性 | 合計 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A. 年輪 / Editorial Timeline | 5 | 5 | 4 | 5 | 5 | 5 | **29** |
| B. 書斎 / Personal Notebook | 5 | 4 | 5 | 5 | 4 | 4 | **27** |
| C. 索引 / Developer Ledger | 4 | 5 | 4 | 4 | 5 | 5 | **27** |
| D. 技術雑誌 / Japanese Web Magazine | 4 | 4 | 5 | 5 | 3 | 3 | **24** |
| E. 静かな蔵書 / Quiet Archive | 5 | 5 | 3 | 5 | 5 | 5 | **28** |

結論はA案を骨格にすること。ただし、A案を完成品としてそのまま採用するのではなく、B案から本人の痕跡、D案から日本語見出しの強弱を少量移植する。E案は、実装途中で装飾を足しすぎたときに戻る基準として使う。

## A. 年輪 / Editorial Timeline


### 一言で表すと

記事を「カードの集合」ではなく、2019年から続く一本の編集記録として見せる。現在の縦線と点をサイト固有の視覚言語へ育てる案。

### トップページ

1. 左寄せの小さなサイト名と2文以内の紹介
2. `記事 / このブログについて / RSS` の通常リンク
3. `2026` から始まる降順の年表
4. 各年の中に、月日、掲載元、題名、短い概要
5. 検索とタグは、年表の上にある小さな道具として置く

37件の現在は、全件をホームで読める量と判断する。100件を超えるまではページネーションを入れず、左側の年索引で長いページを移動できるようにする。`/writings` は検索・タグ・将来の人気順を使う詳細な索引として残す。

### 記事ページ

- デスクトップは、左に公開日・更新日・タグ・目次、右に本文
- 本文は日本語32〜40字/行を出発点に実機比較
- 記事内の「課題と方針」は、一覧と同じ線・点の語彙を使う
- 末尾は「前後の記事」と「同じタグ」だけ。汎用的な3枚カードは置かない
- 古い記事には必要な場合だけ、現在からの短い編集注記を置く

### Aboutとポートフォリオ性

`このブログについて` に「現在」「これまで」「代表して読んでほしい記事」「外部」を置く。職務経歴書の再掲はせず、代表記事3本には選んだ理由を一文付ける。採用側は、トップの時間軸から継続、記事本文から技術判断、Aboutから現在地を読める。

### 視覚仕様

- 背景: 黄みの弱い白または薄い紙色
- 文字: 黒に近い墨色
- アクセント: 深緑、暗い朱、青墨のいずれか1色
- 面: 原則フラット。年の変わり目だけごく薄い背景差を許可
- 線: 1pxを基本に、現在年だけ2pxまたは濃色
- 角丸: 検索入力など機能部品だけ。記事行には使わない
- 書体: 日本語本文はシステムサンセリフ。日付と英数字だけ別書体を比較

### 実装方法

- 年ごとの`section`と時系列の`ol`をServer Componentで出力
- CSS Gridで `year / date-and-line / entry` の3列を構成
- 年だけ`position: sticky`。狭い幅では通常フローへ戻す
- CSS Custom Propertiesで色・間隔・線幅を一括管理
- `text-wrap: balance` は短い見出しだけに限定
- レイアウト専用Client Componentとアニメーションライブラリは追加しない
- 将来の人気順は同じ`WritingTimeline`へ並び順だけ渡し、PV値は表示しない

### モデルページと抽出した要素

- [Anthony Fu — Posts](https://antfu.me/posts): 年ごとの高密度な記事索引
- [Max Böck — Writing](https://mxb.dev/blog/): 日付と題名を中心にした個人ブログの密度
- [Sara Soueidan — Blog archive](https://www.sarasoueidan.com/blog/archive/): 専門性が記事履歴から伝わるアーカイブ
- [Tania Rascia](https://tania.dev/): 本人の短い言葉と最近の記事の優先順位
- 公開実装の参考: [antfu/antfu.me](https://github.com/antfu/antfu.me)、[maxboeck/mxb](https://github.com/maxboeck/mxb)

複製するのは画面ではなく、年を情報構造にする考え方である。

### AIっぽさを避ける仕組み

ヒーロー、数値パネル、CTA、同寸カードを使わず、実在する日付と題名の不均一さをそのまま構図にする。アクセントは「2026」「線」「リンク」にだけ使い、雰囲気だけのグラデーションや生成イラストを置かない。

### リスクと対策

- **単調になる**: 年見出し、掲載元、概要の有無で小さなリズムを作る
- **長くなる**: 年索引と検索を提供し、100件を超えた時点で分割を再評価
- **採用側へ弱い**: Aboutと代表記事への導線をヘッダー直下とフッターに一度ずつ置く

## B. 書斎 / Personal Notebook


### 一言で表すと

完成した技術記事だけでなく、外部記事、短い注記、試行中の関心も「自分の机の上」に並べる。個人ブログらしさを最も強く出す案。

### トップページ

- 短い近況と、最新の年表を同じ紙面に置く
- 年表は一本の線を維持し、欄外に短い編集注記を置ける
- `記事`、`外部で書いたもの`、`メモ` は別カードにせず、掲載元の文字で区別
- 本人が撮った写真や描いた図がある場合だけ、年に1〜2点ほど使う

### 記事ページ

- 本文は静かな一段組
- 注記、後日談、参照リンクを欄外または本文幅内の細い罫線で表す
- コードや図版は必要な記事だけに出るため、通常記事は非常に軽い
- `公開時の自分` と `現在の注記` を書き分けられる

### Aboutとポートフォリオ性

履歴書風の節を作らず、「いま試していること」「よく書くこと」「このサイトの変遷」を短く置く。仕事に関する説明は、公開できる範囲で代表記事の注記へつなげる。

### 視覚仕様

- 温かい白、鉛筆に近いグレー、インク色1色
- 罫線、脚注記号、ページ番号のような編集記号
- 紙テクスチャはCSSノイズや生成素材で常設せず、必要ならごく軽い自作画像を使う
- 手書きフォントは使わない。本人の手書き図があるときだけ画像として使う
- わずかに不均一な余白は許すが、本文の行長と見出し規則は固定

### 実装方法

- Markdown frontmatterへ任意の`editorNote`と`updatedAt`を追加可能にする
- CSSの`aside`とGridで欄外注記を作り、狭い画面では本文下へ戻す
- 写真は`next/image`で寸法を予約し、撮影者・代替テキストを持つ
- Webmentionなどは初回へ入れず、ブログの更新習慣が戻ってから検討

### モデルページと抽出した要素

- [Maggie Appleton](https://maggieappleton.com/): 内容の成熟度や種類を本人の語彙で説明する
- [Max Böck](https://mxb.dev/): 長く育てた個人Webと一つだけ強い遊び
- [Tania Rascia — About](https://tania.dev/me/): 運営方針を本人の短い文で示す
- [Zach Leatherman — About](https://www.zachleat.com/about/): 古い履歴もサイト史として残す
- 公開実装の参考: [MaggieAppleton/maggieappleton.com-V3](https://github.com/MaggieAppleton/maggieappleton.com-V3)

### AIっぽさを避ける仕組み

本人が書いた追記、撮った写真、実在する失敗や関心を装飾の代わりにする。「手作り風」の既製テクスチャや生成イラストは使わない。文言の長さを3項目へ揃えない。

### リスクと対策

- **素材がないと成立しにくい**: 初回は文章と罫線だけで完成させ、本人素材は後から増やす
- **作り物のノート感が出る**: テープ、破れ紙、傾き、手書きフォントを禁止する
- **注記の保守が増える**: frontmatterは任意項目にし、通常の記事作成手順を変えない

## C. 索引 / Developer Ledger


### 一言で表すと

図書目録、変更履歴、ソースコード索引の密度を借り、記事を素早く走査できる開発者向けの帳簿にする案。

### トップページ

- 1画面目から年、日付、題名、タグが多く見える
- 左に固定幅の日付、中央に題名、右に掲載元またはタグ
- 最新記事だけ概要を出し、過去記事は一行を基本にする
- 検索結果件数や選択中タグを明確に表示

### 記事ページ

- メタ情報は狭い左レールへまとめる
- 本文の日本語は通常のサンセリフ。等幅は日付、タグ、コードだけ
- コード、コマンド、差分の見た目に一貫性を持たせる
- 記事の更新履歴がある場合は小さな変更ログにできる

### Aboutとポートフォリオ性

`現在 / 過去 / リンク` を簡潔な行として置く。GitHubは目立つが、contribution graphやスキルロゴの壁は作らない。専門性はタグ数ではなく代表記事の具体的な題名で示す。

### 視覚仕様

- 象牙色または白、濃い墨色、コバルトまたは朱1色
- 細い横罫線と列揃え
- 角丸と影は使わない
- 数字・英字・コードだけ等幅。日本語本文まで等幅にしない
- タグは角丸ピルで囲まず、`#nextjs` の文字リンクにする

### 実装方法

- CSS Gridで列を揃え、コンテナクエリで狭い行を二段へ変える
- 一覧を表組みに見せても、構造は見出し付きの`ol`と記事リンクにする
- 検索は現在のGETパラメータ`query`を維持し、URLを共有可能にする
- JavaScript無効時にも年別一覧と通常リンクを残す

### モデルページと抽出した要素

- [Anthony Fu — Posts](https://antfu.me/posts): 年・日付・題名の圧縮
- [Paco Coursey](https://paco.me/): 短い文章とリンクで活動を伝える
- [Rauno Freiberg](https://raunofreiberg.com/): 少数の原則と精度の高い細部
- [Zach Leatherman](https://www.zachleat.com/): 更新・ビルド・サイト史も個人サイトの内容にする

### AIっぽさを避ける仕組み

「開発者向け」を偽ターミナル、タイプライター演出、緑文字で表さない。実際の日付、タグ、更新履歴を列として使い、意味のある密度で個性を作る。

### リスクと対策

- **冷たく見える**: 冒頭に本人の一文、概要に口語を残す
- **文字が小さくなる**: 密度をフォント縮小ではなく概要の省略と列配置で作る
- **ポートフォリオ感が強まる**: `Projects / Skills` を追加せず、索引対象を記事中心に固定する

## D. 技術雑誌 / Japanese Web Magazine


### 一言で表すと

日本語技術誌や同人誌の編集面を参照し、強い見出し、段差、罫線で記事の重要度を編集する案。五案の中で最も視覚的な印象が強い。

### トップページ

- 最新記事1本だけを大きく扱い、その下から年表へ接続
- 年ごとに「特集」のような短い編集文を任意で置く
- 通常記事はカードにせず、見出しサイズと段組で差を付ける
- 写真や図版は代表記事だけ。すべての記事にサムネイルを要求しない

### 記事ページ

- 大見出しと導入の文字組みを強くし、本文は落ち着いた一段組へ戻す
- 図版、キャプション、引用、コードの種類を明確にする
- 記事ごとのOG画像は同じテンプレートへ押し込まず、文字だけの基本版と図版あり版を用意
- 章番号は内容に合う長文だけに使う

### Aboutとポートフォリオ性

代表記事を「特集」として2〜3本選び、それぞれに技術選定や検証内容を一文で記す。通常のブログ読者には記事の読みどころ、採用側には判断の文脈として同じ文が機能する。

### 視覚仕様

- 白または明るい生成り、黒、朱または群青
- 太い見出しと非常に細い罫線の対比
- 左揃えを基本に、年見出しや最新記事だけ大きな段差
- 日本語表示書体は見出し1ウェイトのみ比較。本文はシステムフォント
- グリッドは非対称だが、本文幅と操作位置は安定させる

### 実装方法

- CSS Grid/Subgrid、Container Queriesで編集面を組む
- `clamp()`で見出しと余白を連動させる
- 画像の有無をfrontmatterで受け、画像なしでも破綻しないレイアウトを基本にする
- フォントはサブセット、自己ホスト、実測後に採否を決める
- スクロール演出ではなく静止画面の階層だけで成立させる

### モデルページと抽出した要素

- [Ahmad Shadeed](https://ishadeed.com/): 強い見出し、図版、記事を一つの編集面に統合
- [Josh W. Comeau](https://www.joshwcomeau.com/): 記事の理解に必要なときだけ独自の表現を作る
- [Sara Soueidan](https://www.sarasoueidan.com/): 長文と専門性を読み物として見せる
- [Kentaro Koga](https://www.taroken.dev/): 日本語の個人サイトで仕事外の関心も同居させる
- 実装判断の参考: [Joshの実装解説](https://www.joshwcomeau.com/blog/how-i-built-my-blog-v2/)

### AIっぽさを避ける仕組み

画像生成で「雑誌風」にせず、日本語の実在見出し、内容ごとの長短、罫線、余白だけで誌面性を作る。全記事へ同じカバー画像を生成しない。特集にする理由を編集文として書く。

### リスクと対策

- **記事追加のたびにアートディレクションが必要**: 通常記事は自動レイアウト、代表記事だけ任意指定にする
- **性能が悪化する**: 初期表示画像1枚以内、表示書体1ウェイト以内を予算にする
- **トップが作品集に戻る**: 大きく扱うのは常に記事であり、自己紹介や架空プロジェクトではない

## E. 静かな蔵書 / Quiet Archive


### 一言で表すと

装飾を限界まで減らし、個人の蔵書目録のように題名、日付、余白だけを残す。最も長持ちし、最も軽い案。

### トップページ

- サイト名、短い紹介、年別記事一覧だけ
- 年表の線は薄く、年の数字と現在位置だけがアクセント
- 概要は最新数件だけ表示、過去は題名と日付へ圧縮
- About、タグ、RSSは通常のテキストリンク

### 記事ページ

- 一段組で本文を最優先
- 記事見出し、公開日、本文、参考資料、前後記事の順
- 目次は長い記事だけ表示し、通常記事では省く
- カード、サイドバー、関連記事グリッドを置かない

### Aboutとポートフォリオ性

短い自己紹介と外部リンク、代表記事3本だけ。派手な演出はないが、ブログ全体の文章とコード品質そのものが評価対象になる。

### 視覚仕様

- ほぼ白、黒、淡い罫線、リンク色1色
- 1種類のサンセリフを基本に、数字だけ字形の相性を確認
- 角丸、影、面の塗りをほぼ使わない
- 見出し段階は3段以内
- 余白と本文幅を主なデザイン材料にする

### 実装方法

- Semantic HTMLと小さなCSSだけで構成
- `prefers-color-scheme`へ自動追従する前に、ライトテーマのコントラストを完成させる
- ホームは静的生成、検索ページだけ必要最小限のClient Component
- 画像、Webフォント、アニメーションなしでも完成形にする

### モデルページと抽出した要素

- [Andy Bell — Blog](https://bell.bz/blog/): 自分のインターネット上の家として段階的に作る
- [Paco Coursey](https://paco.me/): 短い文章とリンクの選択で人柄を表す
- [Max Böck — Writing](https://mxb.dev/blog/): 長期運用を前提とした記事索引
- [Sara Soueidan — Blog archive](https://www.sarasoueidan.com/blog/archive/): 日付と題名の明確な履歴

### AIっぽさを避ける仕組み

「ミニマル」を巨大な余白と巨大な一文だけで表さず、必要なナビゲーションと37件の実データを見せる。テンプレート固有の装飾がない分、文章と時間軸がサイトの顔になる。

### リスクと対策

- **古いだけに見える**: 流体タイプ、現代的なフォーカス、コンテナクエリ、精密なモバイル設計で品質を出す
- **固有性が弱い**: 縦線、年の数字、アクセントの使い方を一貫した署名にする
- **採用側に情報が足りない**: Aboutの代表記事と外部リンクを省かない

## 五案に共通する画面構造

方向を変えても、次の骨格は共通にする。これにより、テーマの比較をページ構造の全面作り直しにしない。

```text
ホーム
├─ サイト名 / 短い紹介 / ナビゲーション
├─ 年索引・検索・タグへの入口
├─ 降順の年表（記事 + 外部記事）
└─ About / GitHub / Qiita / RSS

記事
├─ 題名 / 概要 / 公開日 / 更新日 / 掲載元
├─ 本文
├─ 必要な記事だけ目次・図版・注記
└─ 前後の記事 / 同じタグ

このブログについて
├─ 現在
├─ これまで
├─ 代表して読んでほしい記事（最大3本）
└─ 外部リンク
```

## 選択時に見る順番

1. モックアップの雰囲気ではなく、トップの情報順が自分のブログに合うか
2. 普通の記事を追加するとき、特別な画像や説明が必要にならないか
3. 古い記事と外部記事も、無理なく同じ紙面へ置けるか
4. Aboutを読まなくても個人ブログだと分かるか
5. 5年後に37件が100件になっても、骨格を使い続けられるか

モックアップ内の日本語は視覚比較用であり、実装時はHTMLの実データへ置き換える。画像内の文字精度は採否の判断材料にしない。
