# 年表を使わない10のデザイン方向

すべての案で、ホームの表示記事は3〜6件、全37件は`/writings`へ分離する。縦線、点、年別グループは使わない。

## 比較

10は最も高得点だが、現在の「古いデザインを新しくしたい」という目的に対して変化が弱く見える可能性がある。そのため推奨は01の現代的な文字組みと余白に、04の件数制限、10の直接性を混ぜる構成とする。

## 01. 静かな一段組 / Quiet Column


### 構造

- 最大幅760px程度の一段組
- サイト名、本人の2文、最新4件
- 概要は最新1件だけ、残りは題名と日付
- 下部に`すべての記事 / このブログについて / RSS`

### 見た目

白に近い背景、墨色、青墨または深緑1色。箱、影、カードなし。日本語本文はシステムサンセリフ、サイト名か見出しだけ表示書体を比較する。

### モデル

[Steph Ango](https://stephango.com/)、[Manuel Moreale](https://manuelmoreale.com/)、[Bell](https://bell.bz/)

### 実装

Server Componentと通常のリスト。レイアウト用Client Componentなし。幅、文字、余白、色のトークンだけで成立する。

### 向く場合

記事追加を最も軽くしつつ、古さではなく精度でモダンに見せたい場合。

---

## 02. 左右二室 / Split Reading Room


### 構造

- 左35%: サイト名、短い自己紹介、4リンク
- 右65%: 最新5件
- デスクトップでは左を静止、モバイルでは上から一列

### 見た目

左右の背景色をわずかに変える。中央線は使ってもよいが記事をつなぐ年表にはしない。記事一覧は横罫線だけ。

### モデル

[Lee Robinson](https://leerob.com/index)、[Paco Coursey](https://paco.me/)、[Jim Nielsen](https://www.jim-nielsen.com/)

### 実装

CSS Gridの`minmax()`と`position: sticky`。stickyは十分な高さがある場合だけ。モバイルはDOM順を変えない。

### リスク

左右とも情報を増やすと再びごちゃつく。左は2文と4リンク、右は5記事を上限に固定する。

---

## 03. 表紙と目次 / Cover Story


### 構造

- 最新記事1件を大きな題名と導入で表示
- 下または右に「ほかの記事」3件
- ホームの主見出しは最新記事の題名そのもの
- クリックすると通常の記事画面へ移る

### 見た目

大きな日本語見出しと十分な余白。図は置かなくても成立させる。アクセントは細い下線または一文字だけ。

### モデル

[Frank Chimero](https://frankchimero.com/)、[Ahmad Shadeed](https://ishadeed.com/)、[Josh W. Comeau](https://www.joshwcomeau.com/)

### 実装

最新記事をビルド時に取得し、CSS Gridで表紙と目次を配置。記事画像を必須にしない。

### リスク

更新が止まると表紙も止まって見える。最新記事の日付を誇張せず、Aboutへの入口を残す。

---

## 04. 今月の窓 / Monthly Window


### 構造

- 当月の記事だけをホームへ出す
- 当月0件なら最新3件へ自動フォールバック
- `以前の記事を探す`で全件一覧へ
- 現在取り組んでいることを1文だけ置ける

### 見た目

日記帳の月表示ではなく、通常の一段組。月名は小さく、記事題名を主役にする。カレンダーや日付グリッドは使わない。

### モデル

[Manuel Moreale](https://manuelmoreale.com/)、[Jim Nielsen’s Blog](https://blog.jim-nielsen.com/)

### 実装

サーバー側で`publishedAt`を当月に絞るだけ。クライアント状態なし。更新がない月の表示規則をテストする。

### 向く場合

ホームを常に短く保ち、過去記事を「探す場所」と明確に分けたい場合。

---

## 05. 話題の棚 / Topic Shelves


### 構造

- `フロントエンド / 開発環境 / 振り返り`など3つの話題
- 各話題から代表記事2件だけ
- 最新記事は上部に1件だけ
- 時系列ではなく、何を書く人かを先に伝える

### 見た目

カードではなく、大きな話題名とその下のテキストリンク。背景面を3色に塗り分けない。棚同士は余白か細い罫線で分ける。

### モデル

[Julia Evans](https://jvns.ca/)、[Maggie Appleton](https://maggieappleton.com/)、[Aresluna](https://aresluna.org/)

### 実装

frontmatterの既存タグから、ホーム掲載用の3カテゴリだけ設定ファイルで対応付ける。記事ごとの手編集を増やさない。

### リスク

カテゴリ設計が本人の語彙でないとテンプレートに見える。タグ名をそのまま使わず、記事を見て日本語で命名する。

---

## 06. 一枚の写真 / Photo Anchor


### 構造

- 本人所有の写真1枚
- 写真横または下に2文の紹介と最新3件
- 代表記事やスキル説明はホームへ置かない

### 見た目

写真が色と質感を担い、UI側は白黒に近くする。候補は机、道具、散歩、制作中のメモ。顔写真を必須にしない。

### モデル

[Craig Mod](https://craigmod.com/)、[Elliot Jay Stocks](https://elliotjaystocks.com/)、[Andy Bell](https://bell.bz/)

### 実装

`next/image`で1点だけ、幅・高さ・`sizes`を指定。モバイルで画像を先にするか後にするかは実機比較する。

### リスク

本人素材がないと開始できない。まずグレーの面ではなく画像なし版を作り、写真は後から選ぶ。

---

## 07. 文章地図 / Prose Map


### 構造

- 本人の3〜5文がホームの大半
- 文中の「記事」「Next.js」「外部で書いたもの」などがリンク
- 文の後に最新記事3件だけ
- ナビゲーションをセクション箱にしない

### 見た目

大きすぎない本文と明確な下線。リンク色1色。文章内リンクをボタンやピルへ変えない。

### モデル

[Pedro Duarte](https://ped.ro/)、[Lee Robinson](https://leerob.com/index)、[Paco Coursey](https://paco.me/)

### 実装

通常の`p`と`a`。日本語では一文にリンク1〜2個まで。リンクだけを拾い読みしても意味が通る文言にする。

### リスク

自己紹介が記事より強くなる。最新記事3件を最初の画面内へ必ず入れる。

---

## 08. 夜の読書室 / Night Reader


### 構造

01と同じ一段組だが、夜間の長文読書に振った暗色テーマ。最新5件、概要はなし。

### 見た目

真黒ではなく青みまたは茶色みのある濃色、明るすぎない本文、琥珀または水色1色。ネオン、発光、コード雨、グラデーションは使わない。

### モデル

[Frank Chimero](https://frankchimero.com/)、[Josh W. Comeau](https://www.joshwcomeau.com/)、[Rauno Freiberg](https://raunofreiberg.com/)

### 実装

ライト・ダークを同時に持たず、まずこの案を一つの完成テーマとして評価する。選択された場合だけOS設定または明示切替を検討。

### リスク

ダークテーマだけで「モダン」を作ると汎用的になる。余白と文章の本人性が先で、色は最後に決める。

---

## 09. Swiss Index


### 構造

- 大きなサイト名または短い一文
- 下部に最新4件を整列
- Aboutと外部リンクは上端の小さなナビ
- 日付は列には置けるが、年ごとにまとめない

### 見た目

白、黒、赤または青1色。非対称なグリッド、太いサンセリフ、細い罫線。ポスターのようでも、記事題名は十分な大きさを保つ。

### モデル

[Lynn Fisher](https://lynnandtonic.com/)、[Frank Chimero Design Archive](https://design.frankchimero.com/)、[Rauno Freiberg](https://raunofreiberg.com/)

### 実装

CSS Gridと`clamp()`。文字を画像化しない。モバイルではポスター構図を守らず、一段組へ素直に戻す。

### リスク

ポートフォリオ表紙に見えやすい。最新記事を必ず視界へ入れ、巨大な職能コピーを置かない。

---

## 10. 素のWeb / Native Web


### 構造

- サイト名、本人の一文、最新5件、通常リンク
- 見出しとリストというブラウザ本来の構造
- 全記事、About、RSSは文章中のリンク

### 見た目

システムフォント、青い下線リンク、白または薄灰背景。ブラウザ標準そのままではなく、本文幅、行高、フォーカス、余白だけ精密に整える。

### モデル

[Derek Sivers](https://sive.rs/)、[Jim Nielsen’s Blog](https://blog.jim-nielsen.com/)、[Julia Evans](https://jvns.ca/)

### 実装

最小のCSSとセマンティックHTML。Webフォント、画像、アニメーションなし。現在のNext.js/Markdown基盤で最も小さな差分になる。

### リスク

刷新感が弱い、または単に古く見える可能性がある。サイト固有の一文、リンク色、見出しの字形、余白リズムの四点で意図を示す。

## 10案に共通する記事一覧

ホームが違っても`/writings`は共通にする。

```text
記事を探す
├─ 検索入力
├─ 新着順 / 将来の人気順
├─ 選択中タグ（必要なときだけ）
└─ 記事行
   ├─ 題名
   ├─ 日付または掲載元のどちらかを主にする
   └─ タグ・概要は詳細表示または必要な場合だけ
```

年別見出し、縦線、点は使わない。全件を一列に並べ、検索・タグ・並び替えで探す。外部記事は掲載元と外部リンク記号で判別する。
