# 第4回への反応から推定した好み

## 一文でまとめる

**記事のカバーを中〜高密度の編集グリッドへ並べ、現実の紙や端末画面を少量混ぜた、モダンで技術的な個人ブログ。**

写真そのものを作品として見せるのではなく、記事へ入るための視覚的なリンクとして使う。ポートフォリオ性はProjectsやSkillsではなく、カバーの選び方、画面の作り方、記事内容から自然に伝える。

## 評価から読み取れること

| 第4回案 | 反応 | 推定できること |
| --- | --- | --- |
| 01 | 良さそう | 暗色、高密度、複数画像、明確な記事対応は合う |
| 02 | 良さそう | 明色でも校正面のような密度と連番は合う |
| 03 | 並び方は良い、出方が変 | 横一列は使えるが、写真固有の固定キャプションは不要 |
| 04 | 微妙 | 写真列と文章列が分離しすぎると、記事カバーに見えない |
| 05 | 画像が大きすぎる | 一枚または二枚が画面を占有すると写真ブログになる |
| 06〜10 | 微妙 | 朝昼夜、道具、クロップ、季節、散歩という写真側の物語は不要 |
| 11 | 現実との複合が良い | 紙や端末とWeb UIの境界を混ぜる表現に可能性がある |
| 12 | シンプルすぎる | 余白中心で要素が少ない案は物足りない |
| 13 | かなり良い | 複数の現物・コード・画面を編集グリッドへ置く方向が強い |
| 14 | シンプルすぎる | 文字一覧に小さな装飾だけではデザインの手応えが不足 |
| 15 | 悪くないが難しい | 図は補助ならよいが、主役にするとブログから離れる |
| 16 | 大きすぎる | コードや端末も大判一枚ではなく、カバーの一種として小さく使う |
| 17〜19 | 微妙 | ケーススタディ、QA、外部記事専用の構図はホームの主軸にしない |
| 20 | 色とスタイルは良い | 暗いグレー、生成り、オレンジ、モジュラー配置は候補になる |

## 好きな可能性が高いもの

- 5〜12件程度の記事カバーが同時に見える。
- 同じ長方形だけでなく、横長、正方形、縦長が一つのグリッドで揃う。
- 暗いチャコール + 生成り + オレンジ、または白 + 黒 + 赤の限定色。
- 紙、ノート、コード、ブラウザー画面、汎用端末枠を同じ編集面へ置く。
- 画像の下またはhover時に記事題名、日付、タグが現れる。
- クリックしたカバーが記事ヘッダーへ連続して移る。
- すべてが完璧に揃うのではなく、一部だけ寸法や素材が異なる。

## 嫌いな可能性が高いもの

- 記事と無関係な写真へ、さらに独立した詩的キャプションを付ける。
- 写真一枚が画面の半分以上を占める。
- 朝昼夜、四季、散歩、道具など、写真ブログの企画がホームを支配する。
- 大きな図、コード、端末が単独で主役になる。
- 文字だけに近い極端なミニマル。
- 均一な角丸カードを並べたAI生成風のBento。
- Projects、Skills、経験年数、実績値が目立つ転職用ランディングページ。
- すべての要素が常時動く、またはスクロールを奪う演出。

## 今回の判断基準

30案は次の条件をすべて満たすものに限定する。

1. 各画像が必ず一つの記事リンクに対応する。
2. カバー未指定でもレイアウトが崩れない。
3. 画像を外しても題名と日付で記事を選べる。
4. デスクトップで中〜高密度、モバイルで通常の一列へ戻せる。
5. モーションを無効にしても意味と操作順が変わらない。
6. 写真ブログ、Projects一覧、技術スタック一覧に見えない。
